# Hugging Face DGX Spark 适配排序设计

## 目标

Hugging Face 模型搜索保留完整搜索能力，并优先展示适合当前 DGX Spark 管理环境的模型。NVFP4 是最强的正向排序信号，但“推荐”仍需同时满足当前 vLLM/SGLang 部署链路的基本要求。

## 搜索与排序

后端从 Hugging Face 获取最多 50 个候选结果，为每个结果计算确定性的 `spark_compatibility`，再按适配等级（`recommended`、`compatible`、`review`）、等级内分数和 Hugging Face 原始顺序排序，最后截取调用方请求的数量。这样可以将真正可部署的 NVFP4 模型提升到首屏，同时避免高分但明确需要评估的模型压过可部署结果；同等级同分时保留 Hub 的相关性。

适配评分使用仓库名称、标签和任务类型，不额外逐个请求模型详情：

- NVFP4 获得最高权重。
- `compressed-tensors`、`vllm`、`sglang`、`safetensors`、FP8、AWQ、GPTQ 等当前部署链路可用信号获得正向权重。
- 文本生成、对话和图文生成任务获得小幅正向权重。
- 只有 GGUF 且没有当前运行时支持格式的仓库降低优先级，因为面板暂未管理 llama.cpp 部署。
- 从仓库名称可明确识别为超大参数规模时降低置信度；MoE 的 `NxMB/T` 记法按专家数乘单专家规模估算总参数。明显超过单机合理范围的模型进入 `review`，避免仅因量化标签匹配而占据可部署结果前列。

分数映射为三个等级：

- `recommended`：包含 NVFP4，且没有明显不兼容信号。
- `compatible`：具备当前运行时和权重格式的正向信号，且没有明确的格式或容量风险。
- `review`：元数据不足、格式不由当前运行时直接支持，或存在明显容量风险。

## API 契约

`GET /api/huggingface/search` 的每个结果新增：

```json
{
  "spark_compatibility": {
    "level": "recommended",
    "score": 160,
    "reasons": ["NVFP4 量化", "可由 vLLM 部署"]
  }
}
```

现有字段保持不变。等级是首要排序依据，分数用于同等级排序；两者只用于候选结果排序与提示，不作为下载或部署的硬性拦截条件。对于 `review` 结果，决定降级的容量或运行时原因必须进入前两条原因，保证前端的简洁展示不会只剩正向信号。

## 前端

搜索列表在模型名称旁显示适配标签：

- `DGX Spark 推荐`：成功色，优先用于 NVFP4 推荐项。
- `可部署`：信息色。
- `需评估`：默认弱化样式。

列表描述展示最多两个简短适配原因，并继续显示任务类型、下载量、点赞数和授权状态。布局使用现有 Ant Design `Space` 与 `Tag`，允许自动换行，兼容移动端和深色主题。

## 错误与兼容性

Hugging Face 没有返回标签时仍生成 `review` 结果，不影响搜索。未知标签不会导致错误。接口字段为新增字段，不破坏现有调用方。

## 测试

- 后端单元测试先验证 NVFP4 结果会排在下载量更高的普通模型前。
- 验证同分结果保持 Hugging Face 原始顺序。
- 验证 GGUF-only 结果不会被标记为当前面板可直接部署。
- 验证 NVFP4 与当前运行时支持信号共同出现时返回 `recommended` 和可解释原因。
- 运行完整后端测试、前端测试、类型检查与生产构建。
- 部署到 DGX Spark 后通过真实搜索确认 NVFP4 首屏排序和响应式显示。
